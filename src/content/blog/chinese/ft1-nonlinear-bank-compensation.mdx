[上一篇](/blog/ft1-nonlinear-verification/)把FT-1的线性化模型和非线性6自由度模型做了对比,确认两者吻合。那是对**模型**的检验。这篇要问的是下一个自然的问题:[推力那篇](/blog/ft1-thrust-gamma-speed-hold/)里的航迹角/速度保持PID,是完全照着线性模型设计的——它还能飞得动非线性飞机吗?

大体上能。控制器基本原封不动地迁移过去了:航迹角3.005°(指令3°),速度0.2983 m/s(指令0.30),坡度10.000°(指令10°),而且没有任何饱和——升降舵峰值0.92°(可用25°),副翼4.15°,油门1.271 N(预算±3 N)。这些数字和它在原本设计所依据的线性模型上跑出来的几乎一模一样。

然后你让它压坡度,问题就明显了。

## 10度转弯不该付出16%的空速代价

给10°坡度指令,空速从13.0 m/s冲到15.1——**2.11 m/s,占配平速度的16.2%**。它能收敛回来,所以回路是稳定的,但这个数字本身就不合理。算一下一个平飞的10°转弯到底需要多少:

坡度转弯时升力的垂直分量仍要托住重量,即 `L·cos φ = W`,过载 `n = sec φ`。10°时 `sec 10° = 1.015`——只需要**多1.5%的升力**。而升力正比于V²,所以如果完全靠飞得更快来产生这份升力,速度只需要涨 `√1.015 = 0.77%`,也就是**0.10 m/s**。

仿真里动了理论值的20倍。所以这不是转弯的物理特性,是控制器的问题。

## 原因:这套架构里没有任何环节去要升力

把过程打点出来,机理就很清楚了:

```
   t      phi        V        dV    gamma    alpha    thr N
  10.0    0.00   13.000    0.000    -0.00     0.09    0.000
  12.0    7.92   13.318    0.318    -0.46    -0.15    0.515   <- γ掉下去,油门顶上来
  15.0    9.71   14.666    1.666    -0.56    -0.95    0.462   <- 速度冲到+1.67
  20.0    9.99   14.332    1.332     1.15    -0.77   -0.602
  24.0   10.00   13.194    0.194    -0.09    -0.04   -0.065   <- 最终收敛到理论值+0.1附近
```

侧滑最大只有1.28°,所以这不是副翼的不利偏航。真实的链条是:

> 压坡度 → 升力垂直分量减少 → γ下掉0.86° → **γ环唯一的作动器是油门,于是它加推力** → 但推力不产生升力,只产生速度 → 飞机一直加速到 `L ∝ V²` 把升力补回来 → γ恢复了,而飞机已经快了2 m/s。

这套架构是**升降舵管速度、油门管航迹角**——这个配对是推力那篇里经过论证的选择,对这架飞机是对的。但**两个回路都没有坡度补偿**,没有任何环节去向俯仰通道索要转弯所需的那份额外升力,于是飞机只能靠"加速"而不是"抬头"把航迹角找回来。

想用推力去压住速度是自相矛盾的,因为推力恰恰就是把速度顶上去的那个东西。杠杆必须在升力上。

## 解法:一项按坡度调度的补偿

真实自动驾驶仪都有这个东西,叫bank compensation或者turn pitch bias,本质上就是飞行员压坡度时顺手带一点杆。这里的实现是在俯仰角速率指令上加一项前馈:

```matlab
n_extra   = 1/max(cos(phi), 0.2) - 1;              % = sec(phi) - 1
q_cmd_raw = Kp_u*e_u + int_u + q_ff*dgcmd_f + k_bank*n_extra;
```

反直觉的地方在于:往一个**角速率**指令上加常数,为什么飞机不会一直转下去?不会,因为 `G_q`(升降舵→俯仰角速率)**在原点有一个零点**:恒定的舵偏产生的稳态俯仰角速率是零,它产生的是一个新的配平姿态。所以稳态时 `q → 0`,`ele_ss = Kp_inner · q_cmd`。**一个恒定的 `q_cmd` 实际上是一个恒定的升降舵偏置**,也就是一份恒定的迎角和升力增量。这跟速度环自己的积分器用的是同一个机制。

10°坡度、`k_bank = 2` 时的实测:

| | 升降舵 | **α** | **V** | γ | 油门 |
|---|---|---|---|---|---|
| `k_bank = 0` | 1.112° | **−0.772°** | **14.332** | 1.155° | −0.602 N |
| `k_bank = 2` | 0.557° | **+0.262°** | **12.878** | −0.087° | 0.025 N |

飞机抬头约一度,用姿态而不是速度去产生升力,原本±0.6 N来回折腾的油门安静在0.025 N。

## 增益怎么选的,以及必须如实说明的一点

两个坡度下扫参:

| `k_bank` | 10°坡度 max\|dV\| | 30°坡度 max\|dV\| |
|---|---|---|
| 0 | 2.110 m/s (16.2%) | 19.34 m/s (148.7%) — **失控** |
| 1.0 | 0.859 (6.6%) | 4.83 (37.2%) |
| **2.0** | **0.182 (1.4%)** | **1.49 (11.4%)** |
| 3.0 | 1.067 (8.2%) | 7.54 (58.0%) |
| 4.0 | 2.083 (16.0%) | 19.38 — **失控** |

`k_bank = 2` 在两个幅值上都是**真正的内点最优**,不是边界值。再往上过度补偿会掉速,速度环反扑更狠,30°时又会失控。

有一点必须讲清楚:**这个增益比静态前馈算出来的大了约20倍。** 按升力算,10°坡度只需要约0.04°升降舵;实际有效的是0.88°。原因是这一项不是单独在工作——额外的诱导阻力会掉一点速度,速度环发现后**压杆增速**,把补偿抵消掉一部分。所以 `k_bank` 是一个**闭环调出来的增益,不是开环前馈**,配平点或速度环增益一变就得重调。更干净的做法是把过载指令喂给一个法向过载(Nz)内环,那样增益才有真正的物理含义,速度环也不会这样跟它对抗。

## 30度那个案例:这从来就不是副翼的问题

最有价值的结果来自一个飞机原本根本保持不住的坡度。30°时,未补偿的飞机在 **t = 18.3 s 失控**——空速从13冲到32.7 m/s,掉高29米,侧滑穿过20°。

很容易把这读成"滚转操纵权限不够"。**不是。** 两个对照实验:

- 把油门限幅从3 N提到 **15 N,完全无效**——仍在17.5 s失控,速度仍然到32.7 m/s。升力不足是不可能用推力补的。
- 把滚转内环增益减半,它就活下来了——但这是症状不是原因。在32.7 m/s时动压是配平值的**6.3倍**,滚转回路的有效增益就是设计值的约6.3倍,越过了稳定边界。**这些增益在13 m/s下完全正常**,是未补偿的坡度让飞机加速到了它们不再适用的区域。

加上 `k_bank = 2` 之后,30°这个case就是正常的:空速峰值14.5 m/s而不是32.7,整个指令段坡度稳稳保持。

## 这件事真正说明了什么

控制器几乎原封不动地迁移到了非线性飞机上,这本身是个实实在在的结果——线性模型上的设计是靠谱的。它**没有**带过去的,是一个从来没人写下来的隐含假设:**飞机不会被要求长时间保持坡度**。一个围绕平飞配平点的小信号设计,没有任何理由包含 `sec φ` 这一项,而线性模型也没有办法惩罚它的缺失。

这才是这件事真正的普遍教训。非线性模型找到的不是一个**调参错误**,而是一个**缺失的项**——一个线性化对象在结构上就不可能揭示的东西,因为这个效应对坡度角是二阶的,而线性模型正是在零坡度处展开的。这已经是这个项目里第二次,检验方找到了被检验方自己不可能发现的问题。

还有一个有效性边界需要标明。这些运行被判"失控"时,飞机处于2.5倍配平速度、20°侧滑,已经远离AVL导数适用的包线(围绕13 m/s配平点的线性展开,**无失速模型**)。它的正确含义是:**控制设计在此失效**——而不是对真实飞机之后行为的预测。
